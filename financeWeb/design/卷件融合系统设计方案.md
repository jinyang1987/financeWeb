## 2. 数据模型设计

### 2.1 核心概念：两套编号体系

```
┌────────────────────────────────────────────────────────────┐
│                   编号体系                                    │
├──────────────────────────┬─────────────────────────────────┤
│     卷级档号              │     件级档号                      │
│     (Volume Code)        │     (Item Code)                  │
├──────────────────────────┼─────────────────────────────────┤
│ 赋号时机: 确认组卷时      │ 赋号时机: 记录入档时              │
│ 赋号对象: Volume          │ 赋号对象: ArchiveRecord          │
│ 流水号段: 卷流水号(V001)  │ 流水号段: 件流水号(0001)         │
│ 共享前缀: 全宗-门类-年度   │ 共享前缀: 全宗-门类-年度          │
│  -类别-保管期限            │  -类别-保管期限                   │
├──────────────────────────┴─────────────────────────────────┤
│                 前缀段在两套编号中完全一致                      │
│          仅最后一位流水号段不同（卷号/件号）                    │
└────────────────────────────────────────────────────────────┘
```

**编号生命周期：**
```
采集入档 → 自动赋件号(archiveCode) → 待组卷
                                        ↓
                                  组卷工作台 → 确认组卷 → 赋卷号(volumeCode)
                                        ↓
                                  卷内件保留原件号，新增卷内序号(itemNo)
                                  卷件通过"卷号 ↔ 件号"映射关联
```

### 2.2 新增：案卷（Volume）

```typescript
// volume.ts — 案卷实体
export interface Volume {
  id: string;                      // 唯一标识
  volumeCode: string;              // 卷级档号(=案卷号, 按规则生成)
                                   // 如 Z001-HJ-2026-KP-D30-V001
  title: string;                   // 案卷题名（如 "2026年度会计凭证-第001卷"）
  fondsCode: string;               // 所属全宗号
  archiveType: string;             // 档案类别（凭证/账簿/报表/其他）
  archiveTypeCode: string;         // 档案类别代码（KP/KB/FB/QT）
  year: number;                    // 年度
  retention: string;               // 保管期限（10年/30年/永久）
  retentionCode: string;           // 保管期限代码（D10/D30/Y）
  
  // 物理信息
  totalItems: number;              // 卷内件数（电子件计数）
  totalPages: number;              // 卷内页数（纸质扫描页数）
  pageStart: number;               // 起始页号
  pageEnd: number;                 // 终止页号
  volumeCount: number;             // 册号（同一卷有多册时）
  boxNo: string;                   // 盒号/箱号
  cabinetNo: string;               // 柜号（实体存放位置）
  shelfNo: string;                 // 架号
  
  // 时间
  dateFrom: string;                // 卷内日期起
  dateTo: string;                  // 卷内日期止
  createdDate: string;             // 组卷日期
  createdBy: string;               // 组卷人
  
  // 状态
  status: VolumeStatus;            // 案卷状态
  digitalHash: string;             // 数字化副本整体哈希
  scanned: boolean;                // 是否已完成数字化扫描
  
  // 关联
  categoryConfigId: string;        // 关联的目录配置ID
}

export type VolumeStatus =
  | 'draft'       // 草稿（组卷中，尚未赋卷号）
  | 'numbered'    // 已赋卷号（组卷完成，卷号已生成）
  | 'completed'   // 已完结（卷内目录已打印等）
  | 'transferred' // 已移交档案部
  | 'destroyed';  // 已销毁

// 卷内编目项（Volume Item）
export interface VolumeItem {
  id: string;
  volumeId: string;               // 所属案卷ID
  recordId: string;               // 关联的ArchiveRecord ID
  recordArchiveCode: string;      // 关联记录的件级档号（冗余，方便查询）
  itemNo: number;                 // 卷内件号（顺序号，从1开始）
  pageStart: number;              // 起始页号（纸质中的页码）
  pageEnd: number;                // 终止页号
  title: string;                  // 件题名
  date: string;                   // 日期
 备注?: string;
}
```

> **状态流转：**
> `draft`(草稿，未赋号) → `numbered`(已赋卷号) → `completed` → `transferred` → `destroyed`
>
> 其中 `draft→numbered` 是"赋卷号"的关键步骤，卷号一旦生成即不可修改。

### 2.3 新增：档号编码规则配置（卷级 + 件级）

```typescript
// archiveCodeConfig.ts
//
// 核心设计：一套配置，两套规则
// 同一份规则配置同时定义"卷级档号"和"件级档号"
// 前缀段（segments）共享，只在流水号段区分卷/件

export interface ArchiveCodeRule {
  id: string;
  ruleName: string;                // 规则名称（如 "标准会计档案档号规则"）
  isDefault: boolean;              // 是否默认规则
  
  // ── 档号前缀段（卷和件共享） ──
  // 例如: Z001-HJ-2026-KP-D30
  segments: ArchiveCodeSegment[];
  
  // ── 卷级流水号段配置 ──
  volumeSerial: {
    label: string;                 // 如 "卷流水号"
    length: number;                // 定长（如 3 位: V001-V999）
    paddingChar: string;           // 补位字符（默认"0"）
    prefix: string;                // 前缀标记（如 "V" 或用空串）
    resetOn: 'year' | 'month' | 'never';
  };
  
  // ── 件级流水号段配置 ──
  itemSerial: {
    label: string;                 // 如 "件流水号"
    length: number;                // 定长（如 4 位: 0001-9999）
    paddingChar: string;           // 补位字符（默认"0"）
    prefix: string;                // 前缀标记（通常为空）
    resetOn: 'year' | 'month' | 'never';
  };
  
  // 示例输出
  exampleVolumeCode: string;       // 如 "Z001-HJ-2026-KP-D30-V001"
  exampleItemCode: string;         // 如 "Z001-HJ-2026-KP-D30-0001"
}

export type ArchiveCodeSegmentType =
  | 'fondsCode'       // 全宗号（固定）
  | 'categoryCode'    // 门类代码（如 HJ = 会计档案）
  | 'year'            // 年度
  | 'archiveTypeCode' // 档案类别代码（KP/KB/FB/QT）
  | 'retentionCode'   // 保管期限代码（Y/D30/D10）
  | 'orgCode';        // 机构/部门代码

export interface ArchiveCodeSegment {
  type: ArchiveCodeSegmentType;
  label: string;                   // 显示名称
  length?: number;                 // 定长（不足补位）
  paddingChar?: string;            // 补位字符（默认"0"）
  separator?: string;              // 段分隔符（默认"-"，最后一段后可空）
  order: number;                   // 排序
  fixedValue?: string;             // 固定值（如门类代码 HJ）
  source?: 'fixed' | 'auto' | 'config'; // 来源：固定 / 自动推导 / 用户选择
}
```

**默认规则示例：**

```
卷级档号: Z001 - HJ - 2026 - KP - D30 - V001
          ────   ──   ────   ──   ───   ────
          全宗号  门类  年度   类别  保管  卷流水
                                  期限
          固定   固定  自动   自动   自动  前缀V+3位

件级档号: Z001 - HJ - 2026 - KP - D30 - 0001
          ────   ──   ────   ──   ───   ────
          全宗号  门类  年度   类别  保管  件流水
                                  期限
                                   前缀空+4位
```

**赋号业务逻辑：**

| 维度 | 赋号时机 | 触发条件 | 流水号依据 | 状态变化 |
|------|---------|---------|-----------|---------|
| **件级赋号** | 记录入档时 | Upload确认 / 接口采集完成 / 批量导入 | 按年度+类别+保管期限查当前最大件号+1 | ArchiveRecord.archiveCode 写入 |
| **卷级赋号** | 组卷完成时 | 工作台"确认组卷"按钮 | 按年度+类别+保管期限查当前最大卷号+1 | Volume.draft → numbered |

> ⚠ **赋号不可逆**：一旦赋号（件号或卷号），非特殊审批不得修改档号。系统应记录赋号操作到审计日志。

## 4. 模块详细设计

### 4.1 档案接收 — 数字化副本采集

#### 功能概述
纸质会计档案线下装订成册后，通过扫描/拍照进行数字化，上传至系统并与元数据关联。

#### 界面布局

```
┌──────────────────────────────────────────────────────────────┐
│  档案接收 >> 数字化副本采集                                    │
├──────────────────────────────────────────────────────────────┤
│  ┌─ 步骤栏 ──────────────────────────────────────────────┐  │
│  │  ①选择来源 │ ②扫描/AI解析 │ ③元数据校验 │ ④入卷归档  │  │
│  └────────────────────────────────────────────────────────┘  │
│                                                              │
│  ┌─ 左侧：采集批次列表 ───┐ ┌─ 右侧：当前批次详情 ────────┐ │
│  │  批次编号  │ 日期 │ 状态│ │  文件列表:                  │ │
│  │  B2026001 │ 06-13 │ 待处理│ │  □ 凭证001.pdf  ✅识别完成 │ │
│  │  B2026002 │ 06-12 │ 已完成│ │  □ 凭证002.pdf  ⚠人工确认 │ │
│  │  B2026003 │ 06-10 │ 已组卷│ │  □ 凭证003.pdf  ⏳识别中…  │ │
│  │  ...                      │ │  ┌────────────────────────┐ │ │
│  │  [+ 新建批次]             │ │  │ 智能OCR预览区域         │ │ │
│  └───────────────────────────┘ │  │ [扫描件图片]            │ │ │
│                                │  │ 识别结果:               │ │ │
│                                │  │ 凭证号: 记-056  ✅      │ │ │
│                                │  │ 金额: ¥12,500.00  ✅   │ │ │
│                                │  │ 日期: 2026-01-15  ✅   │ │ │
│                                │  └────────────────────────┘ │ │
│                                └────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

#### 核心逻辑
1. **批次管理**：一次扫描对应一个批次，批次包含多个文件
2. **OCR识别**：自动识别凭证号、金额、日期、类型等关键元数据
3. **文件切分**：将连续扫描的多页按凭证边界自动切开（依据空白页、条码、金额变化等）
4. **人工校验**：对OCR置信度低的条目，人工修正
5. **入卷/归档**：校验通过后，进入"待组卷"池（纸质副本）或直接归档为"仅件数据"

#### 数据流
```
扫描仪 → PDF/TIFF → OCR引擎 → 元数据提取 → 生成ArchiveRecord(source='digitized')
    → 待组卷池（volumeCode为空, status='仅件数据'）
```

## 5. UI 界面设计方案

### 5.1 设计原则

1. **一致性**：延续现有界面风格（蓝白配色、圆角按钮、左侧导航）
2. **清晰分层**：主操作区居中，辅助信息在侧，工具类在顶栏
3. **全流程引导**：复杂操作（如组卷、移交）提供步骤栏
4. **反馈即时**：操作结果通过Toast通知，异常通过Alert展示
5. **批量操作优先**：会计档案常涉及大量条目，批量操作贯穿全流程

### 5.4 VolumeStore 设计

```typescript
interface VolumeState {
  // ── 数据 ──
  volumes: Volume[];
  setVolumes: (volumes: Volume[]) => void;

  activeVolume: Volume | null;
  setActiveVolume: (volume: Volume | null) => void;

  // 卷内条目
  volumeItems: Record<string, VolumeItem[]>;  // keyed by volumeId
  setVolumeItems: (volumeId: string, items: VolumeItem[]) => void;

  // 未分配记录（待组卷条目）
  unassignedRecords: ArchiveRecord[];
  setUnassignedRecords: (records: ArchiveRecord[]) => void;

  // 组卷推荐
  recommendations: VolumeRecommendation[];
  setRecommendations: (recs: VolumeRecommendation[]) => void;

  // 筛选条件
  filters: {
    year: number | null;
    archiveType: string | null;
    retention: string | null;
    fondsCode: string;
  };
  setFilters: (filters: Partial<VolumeState['filters']>) => void;

  // ── 编号引擎 ──
  /** 当前生效的编号规则 */
  activeCodeRule: ArchiveCodeRule | null;
  setActiveCodeRule: (rule: ArchiveCodeRule) => void;

  /**
   * 根据规则生成件级档号
   * 在记录入档时调用
   */
  generateItemCode: (record: {
    fondsCode: string;
    year: number;
    archiveTypeCode: string;
    retentionCode: string;
  }) => string;

  /**
   * 根据规则生成卷级档号
   * 在确认组卷时调用
   */
  generateVolumeCode: (volume: {
    fondsCode: string;
    year: number;
    archiveTypeCode: string;
    retentionCode: string;
  }) => string;

  /**
   * 获取下一个件流水号
   * 按年度+类别+保管期限 查询，自动重置
   */
  getNextItemSerial: (params: {
    year: number;
    archiveTypeCode: string;
    retentionCode: string;
  }) => number;

  /**
   * 获取下一个卷流水号
   * 按年度+类别+保管期限 查询，自动重置
   */
  getNextVolumeSerial: (params: {
    year: number;
    archiveTypeCode: string;
    retentionCode: string;
  }) => number;

  // ── 操作 ──
  createVolume: (volume: Partial<Volume>) => Volume;
  addItemsToVolume: (volumeId: string, recordIds: string[]) => void;
  removeItemFromVolume: (volumeId: string, recordId: string) => void;
  reorderItems: (volumeId: string, itemIds: string[]) => void;

  /**
   * 确认组卷 = 赋卷号
   * 1. 调用 generateVolumeCode() 生成卷号
   * 2. 写入 Volume.volumeCode
   * 3. Volume.status → 'numbered'
   * 4. 更新每条记录的 volumeId / volumeItemNo
   * 5. 记录审计日志
   */
  confirmVolume: (volumeId: string) => void;

  /**
   * 批量赋件号
   * 对未编号的 ArchiveRecord 依次调用 generateItemCode()
   */
  batchAssignItemCodes: (recordIds: string[]) => void;

  // 智能推荐
  generateRecommendations: () => void;
  acceptRecommendation: (recIndex: number) => void;
  acceptAllRecommendations: () => void;
}
```

**赋号时序图：**

```
记录入档 ──────────→ batchAssignItemCodes() ──→ 写入 archiveCode → 待组卷
                                                       ↑
                                              generateItemCode()
                                              getNextItemSerial()

组卷确认 ──────────→ confirmVolume() ──→ generateVolumeCode() → 写入 volumeCode
                   → 更新每条记录 volumeId       ↑
                   → 生成 VolumeItem       getNextVolumeSerial()
                   → 记录审计日志
```
